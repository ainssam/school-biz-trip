# 여비정산 신청서 자동 생성 웹앱 설계

작성일: 2026-08-27

## 1. 목표

교직원이 출장 정보를 간단히 선택하거나 입력하면 기존 여비정산 신청서 양식을 그대로 유지한 HWP와 PDF를 내려받을 수 있는 웹앱을 만든다. 앱은 Vercel에 배포하며 회원가입, 데이터베이스, 신청서 보관 기능은 두지 않는다.

원본 자료는 다음 두 파일이다.

- `★여비정산 신청서 작성요령.hwp`: 제출기한, 증빙, 교통수단별 작성 기준 등 안내 원문
- `여비정산 신청서(2026.5.30.)_하동원.hwp`: 실제 신청서 양식과 값 배치의 기준

두 원본은 수정하거나 덮어쓰지 않는다. 구현용 템플릿은 개인정보와 기존 출장 내용을 제거한 별도 파일로 만든다.

## 2. 성공 기준

1. 사용자는 설치 없이 Vercel 웹주소에서 신청서를 작성한다.
2. 타이핑을 줄이기 위해 가능한 항목은 드롭다운, 날짜 선택기, 체크박스 또는 자동 채우기로 제공한다.
3. 한 번 입력한 내용으로 HWP와 PDF를 각각 내려받을 수 있다.
4. HWP는 원본의 용지, 여백, 표, 셀 병합, 테두리, 글꼴, 글자 크기, 줄 간격을 그대로 보존한다.
5. PDF는 원본에서 만든 빈 PDF를 배경으로 사용하여 고정 문구, 표와 여백을 그대로 보존한다.
6. 생성 자료는 서버나 데이터베이스에 보관하지 않는다.
7. PC와 모바일에서 입력 및 다운로드가 가능하다.

## 3. 사용자 화면

### 3.1 상단 메뉴

- `신청서 작성`
- `작성요령`

첫 화면은 `신청서 작성`으로 한다. 메뉴는 모바일에서도 한 줄 안에서 쉽게 전환할 수 있게 구성한다.

### 3.2 신청서 작성

입력 영역은 다음 순서로 배치한다.

#### 신청자 정보

- 소속
  - 기본값은 `복자여자고등학교`
  - 이전에 입력한 학교를 브라우저 저장소에 보관해 드롭다운 후보로 제공
  - `다른 학교 입력`을 선택하면 새 학교명을 입력
- 직급(직위): 교사, 교감, 교장, 교육행정직 등 드롭다운과 `직접 입력`
- 성명: 직접 입력

#### 출장 정보

- 출장 시작일과 종료일: 날짜 선택기
- 작성일(신청일): 오늘 날짜를 기본값으로 하는 날짜 선택기
- 출장지: 직접 입력
- 출장목적: 직접 입력
- 출장유형: 자가용, 대중교통, 차량동승, 전세버스 드롭다운

#### 운임 정보

- 교통편: 출장유형에 따라 자동 선택하거나 철도, 고속버스, 시외버스, 자가용, 차량동승, 전세버스 등에서 선택
- 출발지와 도착지: 직접 입력하되 브라우저에 저장된 최근 입력값을 후보로 제공
- 등급: 제2호 기본값, 드롭다운 또는 직접 입력
- 금액: 숫자 입력. 자가용, 차량동승, 전세버스는 기본적으로 `미기재`
- `돌아오는 경로 자동 추가`: 가는 경로의 출발지와 도착지를 반대로 복사하고 날짜와 교통편을 유지
- 운임 합계: 숫자 금액만 자동 계산

#### 비용과 첨부

- 숙박비 지급액, 실제 소요액, 초과지출 사유
- 식비 지급액, 실제 소요액, 초과지출 사유
- 첨부서류: 주유영수증, 주차영수증, 하이패스 영수증, 철도·버스 승차권, 숙박 영수증, 기타를 체크박스로 선택
- 기타 첨부서류만 직접 입력

#### 출력

- 입력내용 미리보기
- `HWP 내려받기`
- `PDF 내려받기`
- 필수값이 빠졌을 때는 다운로드를 시작하지 않고 해당 입력칸 바로 아래에 안내

### 3.3 작성요령

원본 안내문의 내용을 웹에서 읽기 쉽게 다음 카드로 나눈다.

- 제출기한과 제출 순서
- 일비·식비 지급 기준
- 당일 및 숙박 출장 기준
- 자가용 이용
- 대중교통 이용
- 차량동승
- 전세버스 이용
- 숙박비와 법인카드 기준
- 영수증 인정 기준
- 기타 공지사항

원문의 의미, 금액, 제출기한과 주의사항은 바꾸지 않는다. 원본 작성요령 HWP에는 교직원 이름과 내부 담당자 정보가 있으므로 공개 Vercel 자산으로 배포하지 않고 로컬 원본으로만 보존한다.

## 4. 문서 생성 방식

### 4.1 HWP

1. 값이 제거된 HWP 템플릿을 서버 함수의 읽기 전용 자산으로 둔다.
2. 다운로드 요청마다 템플릿을 메모리에서 복사한다.
3. 신청자·출장·운임·첨부 값을 지정된 표 셀과 문단에 일괄 입력한다.
4. 용지, 여백, 표 크기, 셀 병합, 테두리, 글꼴과 문단 속성은 수정하지 않는다.
5. 결과를 응답 파일로 보낸 뒤 서버에 남기지 않는다.

HWP 편집은 원본 바이너리를 다시 구성하거나 다른 형식으로 변환하지 않고, 필요한 셀의 텍스트만 교체하는 방식을 사용한다. 원본의 글자 속성까지 유지하기 위해 값이 칸 너비를 넘으면 글자 크기를 자동으로 바꾸지 않고 다운로드 전에 사용자에게 축약을 요청한다.

### 4.2 PDF

1. 개인정보와 출장 값이 없는 HWP 템플릿을 한컴오피스에서 PDF로 한 번 출력해 기준 배경을 만든다.
2. Vercel 함수는 이 PDF의 표나 고정 문구를 다시 그리지 않는다.
3. 입력값만 미리 측정한 좌표에 같은 글꼴, 크기와 정렬로 얹는다.
4. 원본의 여백, 표선, 고정 문구와 페이지 크기는 배경 PDF 그대로 유지된다.

PDF 좌표는 원본 HWP와 기준 PDF를 겹쳐 보며 조정한다. PDF에 얹는 값도 원본 값 칸과 같은 글꼴, 크기, 정렬을 사용한다. 긴 값은 글자 크기나 표 구조를 자동으로 변경하지 않고 다운로드 전에 사용자에게 짧게 수정하라고 안내한다.

### 4.3 파일명

- HWP: `여비정산신청서_성명_출장일자.hwp`
- PDF: `여비정산신청서_성명_출장일자.pdf`

Windows에서 사용할 수 없는 파일명 문자는 자동 제거한다.

## 5. 데이터와 개인정보

- 회원가입, 로그인, 데이터베이스와 서버 저장을 사용하지 않는다.
- 서버 함수는 입력값을 문서 생성에만 사용한다.
- 생성 응답에는 `Cache-Control: no-store`를 적용한다.
- 입력값과 완성 문서의 내용을 애플리케이션 로그에 기록하지 않는다.
- 학교명과 최근 출발지·도착지 후보만 사용자 브라우저에 저장한다.
- 사용자가 브라우저 기록 삭제 기능으로 편의 데이터를 지울 수 있게 한다.
- Vercel 분석 기능을 사용하더라도 신청서 본문이나 입력값을 이벤트 속성으로 보내지 않는다.

## 6. 오류 처리

- 필수값 누락: 해당 필드 옆에서 수정 방법을 안내한다.
- 금액 오류: 음수, 숫자가 아닌 값, 합계 불일치를 차단한다.
- 텍스트 길이 초과: 해당 칸의 최대 길이를 알려주고 축약을 요청한다.
- HWP 또는 PDF 생성 실패: 입력 화면은 유지하고 재시도 버튼을 제공한다.
- 서버 오류 응답과 로그에는 개인정보가 포함되지 않은 오류 코드만 남긴다.

## 7. 기술 구성

- Next.js App Router 기반 단일 Vercel 프로젝트
- 반응형 웹 UI
- HWP 생성 API와 PDF 생성 API를 분리하되 동일한 검증 스키마 사용
- 원본·빈 템플릿·기준 PDF는 버전이 구분되는 읽기 전용 자산으로 관리
- 최근 학교와 출발·도착지는 `localStorage`에만 저장
- 다운로드 응답은 서버 메모리에서 생성하고 임시파일이 필요하면 요청 종료 즉시 제거

## 8. 검증 계획

### 자동 검증

- 필수 입력과 유형별 조건 검사
- 왕복 경로 자동 생성
- 운임 합계 계산
- 파일명 정리
- 네 가지 출장유형별 HWP와 PDF 생성
- 생성 결과에 입력값이 들어갔는지 마스킹된 구조 검사
- 서버 응답의 `no-store` 헤더 검사
- 개인정보가 로그로 출력되지 않는지 검사

### 화면 검증

- PC와 모바일에서 두 메뉴, 입력, 오류, 다운로드 동작 확인
- 드롭다운과 날짜 선택기 키보드 사용 확인
- 긴 출장지와 출장목적에서 화면 및 출력의 넘침 확인

### 문서 검증

- HWP를 실제 한컴오피스에서 열어 원본과 용지·여백·표·글꼴·줄 간격 비교
- 원본과 생성 HWP를 동일 조건으로 PDF 출력해 고정 서식을 겹쳐 비교
- 기준 PDF와 생성 PDF를 겹쳐 고정 요소의 위치 차이가 없는지 비교
- 자가용, 대중교통, 차량동승, 전세버스 각 1건 이상 육안 확인

미리보기나 구조 검사는 보조 수단으로만 사용한다. 한글 호환성 검증은 실제 한컴오피스에서 파일을 열어 완료한다.

## 9. 1차 버전에서 제외

- 회원가입과 권한 관리
- 서버에 신청서 저장 및 과거 신청서 조회
- 결재·전자서명·도장 삽입
- 여러 신청서 일괄 생성
- 학교 전체 목록 API 연동
- 관리자 화면
- 제출 또는 이메일 전송

이 항목들은 1차 버전의 정확한 문서 생성이 확인된 뒤 별도 단계로 검토한다.
