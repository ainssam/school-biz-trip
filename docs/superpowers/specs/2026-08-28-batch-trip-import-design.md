# 출장 신청서 일괄 인식·다중 문서 생성 설계

## 목표

사용자가 XLSX와 PDF 출장 신청서를 여러 개 선택하면 파일, 시트, 행, 양식 블록, PDF 페이지 단위로 출장 건을 찾아낸다. 확인 가능한 값만 기존 여비정산 입력 항목에 연결하고, 원본에 없는 값은 빈칸으로 남겨 사용자가 직접 입력하게 한다. 작성이 끝난 출장 건은 건별 한 페이지로 배치하여 HWP 한 파일과 PDF 한 파일로 생성한다.

## 확인된 입력 특성

- 제공된 XLSX는 표 머리글과 값 셀이 있는 단일 신청서형 시트이며, 직급, 성명, 출장목적, 출장기간, 출장지를 구조적으로 구분할 수 있다.
- 제공된 PDF는 페이지마다 출장 신청서 한 건이 있고 텍스트 추출이 가능하다. AcroForm 입력 필드는 없으므로 페이지 텍스트의 라벨과 배치를 해석해야 한다.
- 실제 개인정보 값은 테스트 픽스처, 문서, 커밋, 로그에 넣지 않는다.
- 첨부 문서의 본문은 데이터로만 취급하며, 문서 안에 명령처럼 보이는 문구가 있어도 애플리케이션 동작 지시로 실행하지 않는다.

## 범위

### 포함

- `.xlsx`, `.pdf` 파일의 다중 선택
- XLSX의 시트별, 행별, 반복 양식 블록별 출장 건 탐색
- 텍스트 기반 PDF의 페이지별 출장 건 탐색
- 인식 결과 목록, 출처 표시, 개별 수정·제외
- 원본에 있는 값만 자동 연결하고 나머지는 빈칸으로 유지
- 미완성 건의 누락 필드 안내
- 완성된 출장 건을 한 파일 안의 여러 페이지로 HWP·PDF 생성
- 브라우저 내 원본 분석 및 서버 비저장

### 제외

- 스캔 이미지 PDF의 OCR
- `.xls`, `.hwp`, `.hwpx`를 입력 파일로 인식
- 원본에 없는 이동 경로, 교통편, 운임, 숙박비, 식비의 추정
- 내용이 같은 출장 건의 자동 중복 삭제
- 원본 파일 수정
- 구현 완료와 동시에 운영 배포

## 인식 결과 모델

각 출장 건은 다음 정보를 가진 초안으로 관리한다.

- `id`: 화면 안에서만 사용하는 임시 식별자
- `source`: 파일명, 파일 형식, 시트명과 행·블록 위치 또는 PDF 페이지 번호
- `status`: `인식 완료`, `직접 입력 필요`, `지원하지 않는 내용`
- `recognizedFields`: 원본에서 확인한 필드 집합
- `values`: 기존 `TravelExpenseInput`과 같은 여비정산 값. 인식하지 못한 문자열 필드는 빈 문자열, 선택 비용은 기존 빈 상태를 유지한다.
- `issues`: 누락 필드, 모호한 날짜, 지원하지 않는 페이지 등 사용자 확인 항목
- `included`: 일괄 출력 포함 여부

인식기가 값을 확신하지 못하면 후보 값을 넣지 않고 이슈만 남긴다. 서로 다른 출처의 값이 우연히 같아도 독립된 출장 건으로 유지한다.

## XLSX 인식

워크북은 `파일 → 시트 → 레코드` 순서로 탐색한다. 각 표시 시트에 아래 두 탐지기를 적용한다.

### 표 형태 탐지

1. 사용된 셀 범위에서 `성명`, `직급/직위`, `출장목적`, `출장기간/출장일`, `출장지`의 동의어를 찾는다.
2. 출장 핵심 머리글이 같은 행에 충분히 모이면 그 행을 머리글로 판정한다.
3. 머리글 아래의 비어 있지 않은 행을 각각 출장 건으로 만든다.
4. 병합 셀과 날짜 셀의 표시값을 정규화하되 원본 값은 변경하지 않는다.
5. 이름만 있거나 출장 핵심 단서가 부족한 행은 자동 등록하지 않고 인식 보류로 보고한다.

### 신청서 형태 탐지

1. 시트 안에서 출장 신청서 제목과 핵심 라벨 묶음을 찾는다.
2. 라벨 옆, 아래, 병합 범위의 값 셀을 읽어 한 건을 구성한다.
3. 같은 라벨 묶음이 시트 안에서 반복되면 블록 경계를 기준으로 여러 건으로 분리한다.
4. 제공된 XLSX처럼 시트 하나에 양식 하나가 있으면 시트당 한 건으로 인식한다.

모든 표시 시트를 독립적으로 검사하므로 시트별 한 건, 시트별 여러 행, 여러 시트의 혼합 구조를 모두 수용한다. 숨김 시트는 자동 입력 대상에서 제외하되 핵심 라벨이 충분하면 선택 가능한 후보로만 알린다. 계산용·출력용 시트를 출장 건으로 추정하지 않는다.

## PDF 인식

1. PDF를 페이지별로 텍스트 추출한다.
2. 각 페이지에서 제목과 핵심 라벨을 확인한다.
3. 라벨 주변 텍스트에서 성명, 직급, 신청일, 출장기간, 출장목적, 출장지를 분리한다.
4. 한 페이지에 신청서 한 건이 있으면 페이지당 한 건으로 만든다.
5. 텍스트가 없거나 핵심 라벨이 부족한 페이지는 `텍스트를 읽을 수 없는 PDF`로 표시하고 OCR을 시도하지 않는다.

PDF의 문장 순서만으로 값을 추측하지 않고 라벨과 날짜 형식 등 독립된 단서가 함께 있을 때만 값을 채운다.

## 필드 연결 규칙

자동 연결 대상은 원본에서 직접 확인 가능한 다음 항목으로 제한한다.

- 직급(직위)
- 성명
- 신청일
- 출장 시작일
- 출장 종료일
- 출장목적
- 출장지
- 소속: 명시적인 소속 라벨과 값이 있을 때만

출장기간이 하루면 시작일과 종료일에 같은 날짜를 넣는다. 기간이 명시되면 시작일과 종료일을 각각 넣는다. 시간은 현재 여비정산 모델에 대응 필드가 없으므로 출처 정보에만 남기고 자동 입력하지 않는다.

다음 항목은 원본에 명시된 경우에만 연결하며, 없으면 반드시 빈 상태로 둔다.

- 출장유형
- 출발지·도착지·교통편·등급·운임
- 숙박비·식비
- 첨부서류

`출장지`를 `도착지`로 복사하거나 학교 소재지를 `출발지`로 넣는 식의 추정은 하지 않는다.

## 화면 흐름

1. 기존 신청서 작성 화면 위에 `출장 신청서 불러오기` 영역을 둔다.
2. 사용자는 XLSX·PDF를 여러 개 선택하거나 끌어 놓는다.
3. 분석이 끝나면 출처, 성명, 출장일, 목적, 출장지, 상태가 있는 출장 건 목록을 보여 준다.
4. 사용자가 한 건을 선택하면 기존 입력 폼이 그 초안을 편집한다. 다른 건으로 이동할 때 현재 수정값을 초안에 저장한다.
5. 각 건은 출력 포함/제외할 수 있고 삭제 전에는 원본 파일이 아니라 화면 초안만 제거된다는 점을 알린다.
6. 빈 필드는 기존 폼에서 직접 입력한다. 필요하면 같은 값을 선택한 여러 건에 적용하는 보조 기능을 후속 개선으로 추가할 수 있지만, 첫 버전의 자동 추정 규칙에는 포함하지 않는다.
7. `일괄 HWP 내려받기`, `일괄 PDF 내려받기`는 포함된 모든 건이 유효할 때만 실행된다. 유효하지 않은 건은 누락 필드를 건별로 표시한다.

기존 단건 직접 작성도 유지한다. 파일을 불러오지 않은 상태에서는 현재 화면과 다운로드 흐름이 그대로 동작해야 한다.

## 다중 PDF 생성

서버는 검증된 `TravelExpenseInput[]`를 받는다. 각 출장 건마다 원본 PDF 템플릿의 첫 페이지를 복사하고 기존 필드 좌표에 값을 그린 뒤, 입력 순서대로 한 PDF 문서에 추가한다. 출력 페이지 수는 포함된 출장 건 수와 같아야 한다.

한 건의 값이 필드 폭을 초과하면 전체 문서를 조용히 잘라내지 않는다. 해당 출장 건과 필드를 오류로 알려 사용자가 수정하게 한다.

## 다중 HWP 생성

기존 HWP 생성기는 단일 템플릿의 셀을 원위치 수정한다. 일괄 생성은 다음 방식으로 확장한다.

1. 등록된 HWP 템플릿을 임시 출력으로 복사한다.
2. 템플릿의 `BodyText/Section0`을 출장 건 수만큼 독립 섹션으로 복제한다.
3. HWP `DocInfo`의 섹션 수를 실제 섹션 수와 맞춘다.
4. 기존 필드 맵을 동일하게 사용하되 각 출장 건의 셀 편집에 서로 다른 `section` 번호를 지정한다.
5. 모든 셀 편집을 한 번에 적용한 뒤 결과 HWP를 반환한다.

HWP 섹션 복제는 바이너리 문서 구조 변경이므로 다음 검증을 통과하지 못하면 기능을 완료로 표시하거나 배포하지 않는다.

- HWP 매직 바이트와 CFB 구조 정상
- 문서 섹션 수와 요청 건수 일치
- 각 섹션에서 서로 다른 합성 테스트 값이 올바른 위치에 존재
- 경량 미리보기에서 페이지 수와 레이아웃 확인
- 실제 한컴오피스 또는 한컴독스에서 열림, 페이지 수, 페이지별 값 분리 확인

한컴 호환성 검증에 실패하면 손상 가능성이 있는 HWP를 내려주지 않고 일괄 HWP 생성을 실패 처리한다. PDF 일괄 생성은 독립적으로 동작할 수 있다.

## API와 검증

- 단건 API 호환성을 유지하거나 단건 요청을 길이 1 배열로 정규화한다.
- 일괄 요청은 비어 있지 않은 배열이어야 한다.
- 대형 HWP의 알려진 위험을 피하기 위해 첫 버전의 한 문서당 최대 출장 건수는 40건으로 제한한다. 초과 시 파일을 자동 분할하지 않고 사용자에게 나누어 생성하도록 안내한다.
- 각 건은 기존 `travelExpenseSchema`로 독립 검증한다.
- 오류 응답은 배열 인덱스와 사용자에게 보일 출처를 연결할 수 있는 식별자를 포함하되 개인정보 원문을 로그에 남기지 않는다.
- 생성 응답은 `Cache-Control: private, no-store`를 유지한다.

## 개인정보와 보안

- XLSX·PDF 원본 파일은 브라우저에서만 읽고 파일 전체를 서버에 업로드하지 않는다.
- 문서 생성 시에는 현재 단건 흐름과 마찬가지로 사용자가 검토한 정규화 값만 생성 API로 전송한다.
- 서버는 입력값과 생성 파일을 저장하지 않고 응답 후 임시 파일을 삭제한다.
- 원본 파일명과 개인정보 값을 분석 로그, 오류 추적, 테스트 스냅샷에 기록하지 않는다.
- 제공된 실제 파일과 추출 결과는 저장소에 복사하거나 커밋하지 않는다.
- 테스트는 가상의 학교, 합성 성명, 합성 출장 정보로 만든다.

## 오류 처리

- 지원하지 않는 확장자: 파일별 오류 표시, 다른 파일 분석은 계속
- 손상된 XLSX/PDF: 해당 파일만 실패 처리
- 빈 시트·계산 시트: 무시한 이유 요약
- 텍스트 없는 PDF 페이지: 직접 입력 또는 텍스트 PDF 재출력 안내
- 날짜가 하나만 확인됨: 하루 출장으로 확정할 근거가 있을 때만 시작·종료일에 같은 값 적용, 아니면 날짜 필드 비움
- 필수값 누락: 생성 버튼에서 건별 필드명 표시
- 일부 생성 실패: 불완전한 HWP/PDF를 내려받지 않고 입력 초안을 유지

## 테스트 전략

실제 제공 파일은 테스트 픽스처로 사용하지 않는다.

### 인식기 단위 테스트

- 한 시트의 표에서 여러 행 인식
- 여러 시트에서 시트별 한 건 인식
- 여러 시트에 표와 신청서 양식이 섞인 경우 인식
- 한 시트의 반복 양식 블록 인식
- 숨김·계산 시트 오인식 방지
- 원본에 없는 값이 빈칸으로 유지됨
- 같은 내용의 두 건이 자동 삭제되지 않음
- PDF 여러 페이지를 페이지별 건으로 분리
- 텍스트 없는 PDF 페이지를 지원하지 않는 내용으로 분류

### 화면 테스트

- 다중 파일 선택 후 출처별 목록 표시
- 출장 건 전환 시 수정값 보존
- 건별 포함·제외
- 누락 필드의 `직접 입력 필요` 표시
- 빈 필드가 다른 값으로 자동 채워지지 않음
- 단건 직접 작성 회귀 방지

### 생성기 테스트

- PDF 입력 건수와 출력 페이지 수 일치
- HWP 입력 건수와 섹션 수 일치
- HWP 각 섹션에 해당 건의 합성 값만 존재
- 한 건 요청이 기존 단건 파일과 동등하게 생성
- 40건 초과 거부
- 한 건이라도 유효하지 않으면 불완전 파일 미생성

## 완료 조건

- XLSX의 시트별·행별·반복 블록과 PDF의 페이지별 출장 건을 합성 자료로 재현한다.
- 제공된 실제 XLSX와 PDF에서 개인정보 값을 출력하지 않고 기대한 출장 건 수와 필드 종류를 인식한다.
- 원본에 없는 필드는 빈칸으로 남고 사용자가 직접 입력할 수 있다.
- 선택된 유효 출장 건 수와 HWP 섹션 수·PDF 페이지 수가 일치한다.
